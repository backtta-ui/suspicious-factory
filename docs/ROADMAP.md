# 이후 개발 범위 — 아직 구현하지 않음

## 2차: 방과 이동 동기화

Godot 4.6.3의 고수준 MultiplayerAPI / ENet을 후보로 서버 권한 전용 headless 서버를 구성합니다. 우선 두 기기에서 검증한 뒤 6~8명으로 확대합니다. 공개 테스트 서버를 배포하기 전 호스팅 방식·예상 월 비용·트래픽 비용을 설명합니다. 현재는 서버를 배포하지 않았고 비용이 발생하는 서비스를 구성하지 않았습니다.

클라이언트는 이동 의도와 외형 선택만 전송하고 서버가 속도·좌표·충돌·인원·준비·방장·시작 조건을 검증합니다. 로컬 입력과 표시용 보간을 분리합니다. 서버가 발급하는 6자리 방 코드와 익명 ID, 인증된 세션별 재접속 토큰을 사용하고 토큰을 빌드에 내장하지 않습니다. 클라이언트 RPC가 임의의 peer ID를 주장하지 못하게 송신 peer로 식별합니다.

## 3차: 서버 권한 추리 게임

역할·승패·사망·미션 상태·방해 쿨타임·회의와 투표 타이머·집계는 서버만 변경합니다. 역할은 해당 플레이어에게만 전송하고 다른 플레이어의 비공개 역할을 전체 상태 스냅샷에 싣지 않습니다. 6/7명은 방해자 1명, 8명은 2명으로 고정합니다. 거리·생존·회의 상태·쿨타임 검증 없이 제거/신고/작업 RPC를 적용하지 않습니다.

실제 터치 미니게임 6개, 유령 표시 범위, 치명적 방해 타이머, 45초 토론과 30초 투표를 단계별로 추가합니다. 미션은 단순 클라이언트 ‘완료’ 신호를 신뢰하지 않고 서버가 발급한 작업 세션·도전 정보·입력 순서·최소 시간 등을 검증합니다. 채팅과 닉네임 검증, 신고·차단도 이 단계부터 설계합니다.

## 4차: 6~8명 실기기 / 출시 준비

접속 종료 유예와 재접속, 방장 위임, 유예 만료 이탈 처리, 살아 있는 역할 수에 따른 승패 재판정, 게임 재시작을 다인원에서 검증합니다. AAB·릴리스 서명·공개 개인정보 처리방침·Data Safety·등급·부적절한 채팅 방지·충돌 수집·저성능 기기·화면 비율·장시간 플레이 검증을 마친 후 출시 준비 상태를 판단합니다.
