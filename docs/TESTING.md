# 1차 테스트 기록 및 휴대폰 점검표

## 이 환경에서 수행한 검증

- Godot 4.6.3 에디터 리소스 import 및 실제 프로젝트 실행
- Linux의 실제 OpenGL Compatibility 렌더링으로 메인 메뉴와 게임 화면 확인 (`builds/menu.png`, `builds/factory.png`)
- `tests/stage1.gd`: 실제 씬을 불러와 물리 프레임과 터치 이벤트를 실행한 **33개 검사 통과** (`builds/test-results.txt`)
- APK 서명·최소 OS·가로 모드·ABI·권한·정렬 확인은 `builds/apk-verification.txt` 참고

자동 검사는 메뉴 로딩, 9개 외형 조합, 캐릭터 생성, 추적 카메라 활성, 조이스틱 이동, 외벽·방벽·컨베이어 충돌, 문 통과, 일시정지·재개, 백그라운드 전환, 서로 다른 손가락의 입력 소유권, 7개 방 출입문 통과, 메뉴 복귀와 재시작을 확인합니다.

**실제 삼성 갤럭시와 Android 에뮬레이터에서 실행하지 않았습니다.** 화면 캡처는 Linux 실행 결과이며 APK의 모바일 실측 결과가 아닙니다. 프레임 속도, 기기별 발열, 실제 터치 감도, Android 생명주기, 키보드 표시와 노치 대응은 아래 휴대폰 테스트가 필요합니다.

## 직접 해볼 순서 (약 5분)

1. 앱이 가로 화면으로 켜지고 한글이 보이는지 확인합니다.
2. 꾸미기에서 파란 모자+초록 조끼, 초록 모자+파란 조끼를 바꿔봅니다. 모자 없음과 기본 작업복도 확인합니다.
3. 닉네임을 바꾸고 출근합니다. 앱을 다시 열어 외형과 닉네임이 남아 있는지 확인합니다.
4. 조이스틱을 사방으로 움직여봅니다. 손을 떼면 멈추는지 확인합니다.
5. 벽과 기계를 향해 밀어봅니다. 통과하면 안 됩니다. 문으로는 들어갈 수 있어야 합니다.
6. 중앙 복도를 좌우로 다니며 7개 방을 방문합니다. 구역명과 방문 수가 바뀌고 카메라가 따라오는지 확인합니다.
7. 생산라인의 노란 !에 접근해 ‘설비 확인’을 누릅니다. 안내 문구가 나타나야 합니다.
8. 조이스틱에 손을 올린 채 다른 손가락으로 설정을 누릅니다. 이동이 멈춰야 합니다.
9. 홈 화면으로 나갔다가 복귀합니다. 휴식 화면이 나타나고 ‘계속하기’를 누를 때까지 움직이지 않아야 합니다.
10. 설정 → 메인 메뉴 → 공장 들어가기로 다시 시작합니다.

실패하면 휴대폰 모델, Android 버전, 실패 단계, 재현 순서와 화면을 기록해 주세요. 필요하면 USB 연결 상태에서 `adb logcat`으로 로그를 볼 수 있습니다. 이번 버전에는 원격 충돌 로그 수집이 없습니다.

## 빌드 중 해결한 문제

- 홈 경로 쓰기 제한: XDG 데이터·설정·캐시를 `/workspace/toolchain`으로 분리
- 기본 네트워크 및 Java SDK Manager 다운로드 실패: 공식 ZIP 직접 설치
- 비 Gradle 빌드의 Min SDK 재정의 제한: 공식 템플릿 Manifest의 최소 OS 정수만 29로 변경
- Android export의 빈 설정 오류: Android용 ETC2/ASTC import 설정 활성화

## 다음 단계 진입 조건

사용자가 실제 갤럭시에서 이 APK의 이동·충돌·카메라를 확인한 후 2차 멀티플레이 구현으로 넘어갑니다. 이 코드에는 완료되지 않은 네트워크 버튼이나 가짜 접속 기능을 넣지 않았습니다.
