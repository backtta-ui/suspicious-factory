# 도사 2.0.10 — 공통 로딩 및 전환 안정화

기존 Godot4.6.3/GDScript Android 프로젝트에 적용했다. 새 프로젝트/서버/유료 에셋은 만들지 않았다. 캐릭터·꾸미기·UI·도술·맵 지형·저장 형식·멀티플레이 규칙을 보존한다. 서명/패키지/가로 화면도 유지한다. 기준 `4a8648699590ae146df60015c3a78241c36164e0`, 백업 `backup/dosa-2.0.9-before-loading`.

## 실제 원인과 최적화

1. 광장 `plaza_navigation._init()`가 입장마다3,040개 후보 연결선을10px 간격으로 실제 지형에 다시 대조했다. [이전 측정](loading-2.0.10/baseline.json)에서 광장 동기식 생성은4,684~4,721ms였다. 검증된3,019개 연결을 작은 데이터 파일로 저장해 재사용한다. 새 테스트에서 후보3,040개 전체를 기존 `segment_clear()` 판정과 다시 비교해 동일함을 확인한다. 지형/길찾기 규칙을 변경한 최적화가 아니다.
2. 궁궐·해안·수련 바닥과 일부 그림/다리 이미지는 `load()`로 처음 읽으면서 메인 스레드를 점유했다. 필요한 목적지 리소스를 `ResourceLoader.load_threaded_request()`로 먼저 준비하고, `THREAD_LOAD_LOADED` 확인 후에만 `load_threaded_get()`을 호출한다. 미완료 리소스에 `get()`을 호출해 기다리게 하지 않는다.
3. 숲의94×68 길찾기 셀, 건물·충돌·환경 오브젝트를 한 번에 생성했다. 재사용 `WooBuildBudget`의2.5ms CPU 작업 예산으로 생성 작업을 프레임에 나눈다. 빠른 기기에서는 예산 안의 작업을 같은 프레임에서 계속하므로 고정 프레임 지연을 반복하지 않는다. NPC 생성도 프레임을 나눈다. 모든 노드/SceneTree/Physics 연결은 메인 스레드에서 수행한다.
4. 이어하기는 기본 광장 뒤에 저장된 그림 세계를 동기식으로 복원했다. 해당 저장 목적지의 리소스도 미리 준비하고 광장과 그림 세계 양쪽 `build_ready`를 기다린다.
5. 맵 생성 직후 곧바로 입력이 풀리던 경로는 노드 준비, 물리/처리 프레임, 실제 캐릭터·현재 카메라 확인을 거치도록 했다. 실제 생성 전에 최소2번의 처리 프레임을 양보해 로딩 화면에 렌더 기회를 준다.

**2.5ms는 Godot/드라이버 전체 프레임 제한이 아니다.** 단일 엔진 호출·첫 폰트/텍스처/GPU 준비와 OS 스케줄링은 그보다 길 수 있다. Android에서 끊김0이나60FPS를 보장했다고 주장하지 않는다.

## 공통 구조와 연출

- `loading_manager.gd`: 목적지/안내문구, 요청 세대 번호, 중복 요청 차단, 비동기 리소스 상태, 임시 리소스 보유/해제, 노드 준비 대기, 실패/재시도, 최근64개 측정 기록.
- `loading.gd`: 기존 공통 UI의 남색·먹빛, 재사용 부적 아이템 아트, 은은한 문양 빛, 회전하는 푸른 도력, 작은 입자와 구름 장식. 저품질 설정에서는 입자 수를 줄인다. 가짜 퍼센트는 없다.
- `bootstrap.gd`/`bootstrap.tscn`: 같은 로더로 원래 `main.tscn`과 의존 리소스를 준비한 후 기존 타이틀로 넘긴다. 노드 인스턴스 생성은 메인 스레드다. 앱 시작 전에 발생하는 엔진/그래픽 드라이버 초기화는 기존 native splash 영역이며 이번 Script 측정에 포함하지 않는다.
- 기존 그림 입장/역방향 도술 연출을 보존했다. 버튼 직후 같은 로딩 컨트롤러가 입력을 잠그고, 도술 연출 중에는 하단 부적/도력/안내로 표시한다. 실제 맵 준비 때 전체 로딩 화면으로 바뀐 뒤, 준비 완료와 기존 마무리 연출이 끝나야 입력을 풀어준다.
- 현재 맵과 필요한 리소스만 유지한다. 그림 목록을 열어 둔 동안에는 작은 그림 미리보기들을 보유해 스와이프할 때 다시 읽지 않는다. 목록을 닫으면 보유 참조를 해제한다. 모든 플레이 맵을 계속 메모리에 올리지 않는다. 기존 광장 인스턴스를 보존하는 복귀 구조는 유지한다.

## 적용 경로

| 경로 | 실제 적용 |
|---|---|
| 앱 시작 → 기존 타이틀 | 같은 부적 로더 + 원래 Main 장면 비동기 리소스 준비 |
| 타이틀 → 광장 / 이어하기 | 즉시 로딩, 광장·배우·NPC·카메라·HUD 준비 확인 |
| 광장 → 그림 선택 | 그림 리소스 준비 후 기존 캐러셀 표시 |
| 그림 선택 → 숲/궁궐/바다 | 목적지별 문구, 기존 도술 연출, 실제 지형/충돌 준비 |
| 그림 세계 → 광장 | 역방향 연출·공통 로딩, 기존 위치/방향/카메라 복원 |
| 광장/모험 → 수련 | 실제 바닥 준비, 동일 기존 수련 세션, 임시 권한 분리 |
| 수련 → 원래 공간 / 광장 | 공통 로딩, 임시 상태 정리와 원래 인스턴스 복원 |
| 임무 재시작 | 같은 로더로 새 숲 준비, 기존 재도전 HP/도력/몬스터 규칙 유지 |
| 캐릭터 탭/꾸미기 변경 | 기존 메모리 내 배우 갱신이므로 불필요한 맵 로딩 화면을 추가하지 않음 |
| 멀티 서버 연결 | 같은 시각 컴포넌트에 연결 대기·취소 제공. 맵 로딩 플래그와 별개. 실패/취소 때 기다림 화면을 제거하고 기존 주소/오류 안내로 복귀 |

문구는 최초 세계, 광장, 여우의 숲, 달빛 궁궐, 붉은 달의 바다, 수련, 광장 복귀, 다른 도사 연결을 구분한다. 서버의 기존75초 절전 깨우기/재접속 정책은 바꾸지 않았다. 접속 실패를 계속 맵 로딩 중인 것처럼 표시하지 않는다.

## 예외 및 저장 보호

- 입력/조이스틱 캡처를 요청 시작 때 취소한다. 로딩 중 동일 요청은 다시 시작하지 않는다.
- 준비 중 Android 뒤로가기는 장면을 중간 상태로 노출하지 않는다. 실패 안내에서는 뒤로가기로 안전한 화면에 돌아갈 수 있다. 시작 리소스 실패 시에는 재시도/종료를 제공한다.
- 리소스 누락/로드 실패는 명시적인 실패 화면과 재시도로 처리한다. 정상적인 긴 로딩을 제품의 짧은 timeout으로 강제 실패시키지 않는다. 자동 테스트에만30초의 멈춤 감지 deadline이 있다.
- 지도/캐릭터/카메라 실패는 유지된 광장 또는 타이틀로 복구한다. 카메라가 없어졌다면 안전한 광장 카메라를 재생성한다.
- 준비 중 저장 호출은 마지막 완료된 저장을 덮어쓰지 않는다. 실제 플레이 준비 완료 후 기존 저장 함수를 호출한다. 수련은 실제 해금/장착/아이템/성장/승리 기록을 변경하지 않는다.
- 로딩 중 background 상태를 새 세션/타이틀 오디오에 전달하고, foreground 복귀 시 같은 준비 완료 상태를 복원한다. 실제 Android OS 강제 종료/화면 잠금 검증과는 구분한다.

최종 foreground 표본에는 실제 background 전환 주입이 없다. 별도 기능 검사 표본에는 background 통지가 포함되어 있으며, 실제 Android OS/화면 잠금 시험은 아니다.

이전의 ‘동기식 코드 실행시간’과 새 ‘전체 입력 준비시간’은 서로 다른 지표다. 모든 맵의 총시간이 빨라졌다고 주장하지 않는다. 숲처럼 짧은 작업도 여러 프레임으로 나누면 총 전환 시간은 늘 수 있으며, 목적은 메인 스레드 장시간 독점을 제거하는 것이다. `playable_ms`는 마무리 연출과 foreground 입력 복구 준비까지 포함하며(background 표본의 OS 복귀 대기 시간은 제외),, `elapsed_ms`는 공통 로더의 준비 완료까지다. 실패 주입 표본의 `status: FAIL`은 의도한 오류 발생 기록이며 오류 복구 검사가 실패했다는 뜻이 아니다.

## 검증과 남은 한계

제품 코드와 별개인 테스트 드라이버에서 실제 요청, 중복 입력, 세 그림 첫/반복 입장, 저장된 그림 이어하기, 수련, 광장 복귀, 누락 리소스, 재시도, 카메라 소실, 저장 보호를 검사한다. 기존 ‘고정 몇 프레임 뒤 준비 완료’ 가정은 실제 readiness 대기로 보강했다. 전환 중 입력 잠금 검사 자체는 중간 상태를 계속 확인하도록 별도로 유지했다.

중간 전체 검사에서는 두 테스트 가정 오류를 발견했다. (1) 기존 시작 검사가 리소스 준비 전에 배우를 조회했다. (2) 범용 readiness helper가 전환 중 상태 검사까지 기다려 버렸다. 준비 후 검사에만 기다림을 적용하고, 전환 중 입력 잠금/중복 요청 검사는 그대로 실행하도록 수정했다. 중간 실패를 최종 성공으로 재사용하지 않는다.

- PASS/FIXED: 최종 전체 체크포인트 및 APK 검사 후 아래에 실제 결과를 기록한다.
- BLOCKED: 실제 Galaxy 터치·노치·화면 잠금·Android OS kill·GPU 초기화·발열·메모리·FPS. 연결된 실기기가 제공되지 않았고 ADB도 읽기 전용 홈 제약으로 초기화되지 않았다.
- BLOCKED: 배포된 공개 서버와6~8대 실제 인터넷 연결. 로컬 소켓 검사를 공개 온라인 검사로 보고하지 않는다.
- 남은 한계: 드라이버/폰트/원자적 엔진 호출의 모든 일시적 끊김을 제거한 보장은 없다. 일반 UI 미술·도술 이펙트·미지원 의상 등 이전 QA 미완료는 이번 로딩 작업으로 완료 처리하지 않는다.

최종 APK와 배포 링크는 아래 검증 결과에 기록한다.
